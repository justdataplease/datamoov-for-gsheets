# Adding a DataMoov Sheets connector

DataMoov Sheets is a standalone Apps Script app. It borrows DataMoov's registry architecture and the campaign optimizer's report definitions; it does not call either backend. It uses a workflow inspired by [Supermetrics query creation](https://docs.supermetrics.com/docs/how-to-create-a-supermetrics-query-in-google-sheets): choose a source and account, select a report/date range/fields, choose an output location, and refresh a saved report.

One file under `src/connectors/` calls `dmvRegisterConnector_` with its metadata, credential fields, exact allowed hosts, and report definitions. The sidebar, storage, transport, scheduler, preview, and Sheets writer must stay independent of provider identities. A new compatible connector must work without adding a switch or provider allow-list to those shared layers.

Each report declares `id`, `label`, `description`, `fields`, `configFields`, `dateRange`, and `fetch(ctx)`. Optional `discoverFields(ctx)` returns account-specific column descriptors; the catalog derives the "Load columns" button from its presence, so do not declare a separate flag. Use the helpers in `dmv_connector_helpers.js`: `dmvSelectFields_(ctx.fields, available)` resolves the selection, `dmvNeedsDiscovery_` tells whether a discovery call is required, `dmvNumber_`/`dmvTextValue_` coerce provider values, `dmvAppendPage_` enforces the row budget, `dmvUtcWindow_` gives the inclusive date range in UTC milliseconds, and `dmvGoogleAuthFields_`/`dmvBearer_` cover Google authorization. Fields use `{key,label,type,role,default}`. Mark a small default set explicitly. A credential descriptor uses `secret:true` or `type:'password'`; secrets are never returned by bootstrap or connection summaries. Conditional forms use `showWhen:{key,value}`.

`fetch` returns `{columns,rows,metadata}`. Each row is an object keyed by its declared columns. Complete all required pagination or throw. Never silently truncate, manufacture aggregate totals from a sample, or combine nonadditive metrics. Set `metadata.complete:true` only after the full selected report succeeds. Incomplete/truncated results and row-budget overflow are rejected before writing.

The context supplies validated dates, selected fields/configuration, credentials, the row limit, `checkDeadline()`, `http(request)`, and `accessToken()` for declared Google scopes. The transport enforces exact HTTPS hosts, disables redirects, limits retries and execution time, and keeps credential-bearing errors out of logs. Use `retrySafe:true` only for idempotent read requests. Do not fetch credentials from a sibling connector.

Reports default to 1,000 rows and cannot exceed 20,000 rows or 80 output columns; the shared size guards reject anything that will not fit one Apps Script run or one Sheets batch. The writer checks ownership/overlap and submits values, stale-result clearing, and number formats in one Sheets batch. String values are written explicitly as strings, preserving long IDs and preventing formula interpretation. A SHA-256 receipt verifies the previous typed cell values before refresh; manual edits, formulas, shifted/deleted cells, or missing receipts stop replacement. Cells outside the report footprint remain unchanged.

Connections and saved report definitions are private to the current Google user. Reports are associated with an explicit spreadsheet ID. One hourly trigger per user and spreadsheet checks hourly/daily/weekly report schedules; it never removes unrelated triggers. Schedules are approximate intervals, not exact-time commitments. Native Google or service-account credentials are appropriate for unattended refreshes; pasted expiring access tokens require replacement.

Test the real adapter with provider-shaped fixtures for paging, empty results, custom fields, zero/false/null values, row limits, fatal authorization errors, and incomplete data. Test shared changes through an arbitrary connector identity. Passing offline tests does not certify live API permissions, billing, Google authorization, or provider-side field availability.

Run `npm run check`, `npm test`, and `npm run test:browser` as applicable. Publish only to your recorded development project with `npm run push:dev`.
